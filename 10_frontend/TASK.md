# 10_frontend：多角色用户界面

## 职责

- 提供学生、教师、家长和管理员所需的最小页面；
- 展示测评状态、报告、引用、审核状态和安全提示；
- 通过 Backend API 完成交互，不直接访问内部服务；
- 处理加载、空结果、阻断、待审核、失败和权限不足状态；
- 保持普通用户界面易懂，并隐藏不必要的模型/Provider 细节。

## 输入

- Backend 的 api.v1 响应；
- 已确认的角色权限和产品文案；
- 合成测评案例和报告 fixture；
- 设计/无障碍约束及安全提示配置。

## 输出

- 可运行的角色页面、路由和组件；
- 测评答题流程；
- 报告和知识来源展示；
- 教师/管理员人工复核交互；
- 可复现的 UI 状态 fixture 和使用说明。

## 禁止事项

- 不直接连接数据库、向量库、模型或文件系统；
- 不在页面中展示姓名、学号、原始回答或内部 Prompt；
- 不隐藏 high/crisis、safety_blocked 或 needs_review 状态；
- 不把 Mock 数据标记为真实学生结果；
- 不新增未经批准的心理解释、风险承诺或紧急联系方式。

## 接口

- 只消费和调用 /api/v1 端点；
- 使用统一 request_id/trace_id 处理错误反馈；
- 报告页面展示 generation status、review status 和 citation；
- 审核动作调用 reports review API，不能直接修改本地状态冒充成功；
- 所有用户可见文案须与已确认的产品边界一致。

## 验收标准

- 学生端能完成合成测评流程并显示完成状态；
- 教师端能看到受控报告、来源和人工复核状态；
- 家长端只看到授权范围内的支持内容；
- high/crisis 情况明确显示阻断/转介状态，不显示未经审核的个性化建议；
- 桌面和移动布局、键盘操作、焦点、对比度和错误提示完成定向检查；
- API 不可用、无结果、权限不足和过期页面都有可理解反馈。

## 交付物

- 页面、组件和路由；
- 角色权限到 UI 的映射；
- 合成数据状态展示 fixture；
- 无障碍和响应式检查记录；
- UI 文案清单及 Humanizer/Vale 检查说明。
