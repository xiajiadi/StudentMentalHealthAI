# Reviewer / Safety Surface

## 目标

把需要人工确认的安全状态呈现为工作流变化：普通生成停止，复核员查看最小必要信息并执行明确的通过 / 退回动作。它不是红色告警墙，也不是自动通知中心。

## 复核队列 `/reviewer/queue`

队列显示合成案例标识、进入原因的抽象安全级别、当前状态、更新时间和进入详情动作。支持状态与优先级筛选；队列加载、空队列、筛选无结果和可恢复失败都有专门文案。

## 复核详情 `/reviewer/cases/:id`

内容顺序：安全工作流 callout → 当前状态与期待动作 → 最小元数据 → 时间线 → 已审核依据 → 操作面板。高优先级状态必须显示：

> 普通生成已暂停，等待人工复核

主动作是“通过”或“退回”，需要确认对话框和可选备注；动作提交支持幂等冲突和可恢复错误。处理后页面进入 resolved 状态，不再显示可误触的重复普通生成入口。

## 安全边界

- 不显示原始分类器分数、内部规则、模型 trace 或临床标签；
- 不发送监护人、紧急服务或站外消息；
- 前端只呈现 adapter 返回的状态，不自行实现 Safety policy；
- “人工复核”本身是安全工作流状态，不由红色、图标或颜色单独表达。

## 密度与可访问性

复核表面 Design Dials 为 Variance 2 / Motion 2 / Density 6。队列在移动端堆叠为案例卡；详情的状态、时间线和按钮有清晰标题、键盘焦点、Dialog 语义和错误关联。
