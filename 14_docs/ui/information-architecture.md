# 信息架构：Round 1

## 产品主线

Round 1 只交付一条可验证的支持工作流：

```text
登录
  ├─ 学生首页 → CAT Focus Mode → 学生结果
  └─ 教师概览 → 学生列表 → 学生详情
                         └─ 复核队列 → 复核详情 → 通过 / 退回
```

这是教育支持产品的“测 → 译 → 用 → 验”路径，不把模型、检索或测量工程过程作为学生导航。

## 角色与入口

| 角色 | 入口 | 主要任务 | Round 1 暴露范围 |
| --- | --- | --- | --- |
| 学生 | `/student/home` | 开始测评、查看最近结果、理解下一步 | 仅学生可理解的摘要与行动 |
| 教师 | `/teacher/overview` | 查看班级支持概览、进入学生详情 | 合成班级数据、教育支持摘要 |
| 复核员 | `/reviewer/queue` | 处理需要人工确认的安全工作流 | 最小必要元数据、状态、审核依据 |
| 家庭 / 监护人 | 暂不开放 | 后续接收经确认的沟通材料 | 本轮只记录产品边界，不实现 |

## 全局导航

- 学生顶栏：品牌、我的支持、最近结果、退出。
- 教师侧栏：概览、学生、支持流程、范围说明、账户。
- 复核员侧栏：复核队列、已处理、范围说明、账户。
- CAT 独立 Focus Layout：返回入口、题目、选项、保存 / 完成；不显示常规侧栏。

## 导航规则

- 当前页面必须同时有文字和稳定的蓝色锚点，不只依靠颜色。
- 教师和复核员桌面侧栏约 256px；小于 1024px 变为可关闭的移动抽屉。
- 学生不看到教师 / 复核员工作区，也不看到 theta、SE、IRT、模型评分、向量相似度或原始风险标签。
- 未登录访问受保护路由时回到登录；角色不匹配时回到该角色首页。
- Parent、Marketing、复杂 Admin、真实通知和真实后端接入都是后续边界。

## 状态原则

每个旗舰表面都定义 loading、empty、error、partial、success 或 resolved 状态；状态使用文字、图标、结构和动作的组合，不只使用红黄绿颜色。
