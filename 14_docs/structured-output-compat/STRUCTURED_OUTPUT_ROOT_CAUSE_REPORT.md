## 2. Exact Product Failure

The current product-shaped prompt is generated by
`09_backend/src/smhai_backend/domains/support/service.py` in
`SupportService._build_prompt`. It contains the exact accepted chunk identities
as a comma-joined `source_chunk_ids` value.

The current request uses `num_predict=384`. Ollama returns HTTP `200`, but the
response ends in the middle of the second suggestion's `source_chunk_ids`
array. RuntimeService receives `INVALID_STRUCTURED_OUTPUT` with JSON parse
line `26`, column `9`; Backend consequently returns HTTP `502`.

This is a provider output failure, not a successful structured object that is
rejected by semantic validation.

## 3. Direct Ollama Result

The native response is malformed JSON, with:

- `done=true`;
- `done_reason=length`;
- `prompt_eval_count=177`;
- `eval_count=384`;
- response length `700`;
- response SHA-256 `0724991b852d678eba4729eb25fddb875a04522d60fb6168d4049bc7d2746d85`.

The neutral control from the same model, schema, seed, context and options
parses successfully. The exact accepted chunk IDs cause a longer structured
candidate under this model/prompt combination, but the decisive failure
condition is the exhausted output budget.

## 4. RuntimeService Result

The actual `OllamaProvider` request returns the same native response text and
raises `INVALID_STRUCTURED_OUTPUT` during provider-native structured parsing.
The RuntimeService `_validate_response` second validation is not reached,
because no `ProviderResponse` exists after the provider boundary fails.

Replaying the identical provider text through `RuntimeService.parse_structured`
also fails at line `26`, column `9`. No malformed JSON is accepted and no
fallback or repair is involved.

## 9. Minimal Trigger

The smallest operational reproducer is:

1. the current product prompt with all five accepted chunk IDs;
2. the actual generation content schema sent through Ollama `format`;
3. the formal model/digest and fixed generation options;
4. `num_predict=384`.

The provider emits a response longer than the available output budget and
terminates with `done_reason=length`. The JSON parser then correctly rejects
the incomplete candidate.

## 10. Root Cause Class

Primary class: **`OUTPUT_TRUNCATION`**

Secondary factor: the formal model's structured-output behavior emits repeated
exact provenance identifiers for this prompt, making the raw accepted
provenance representation longer than the existing budget. This is a model
response-length limitation under the current request, not permission to
neutralize or replace provenance identities.

## 11. Owning Module

The proven owning module is **09_backend**. The request budget is set in
`09_backend/src/smhai_backend/integrations/llm.py`,
`HttpLLMRuntimeClient.generate`, where `max_output_tokens` is hard-coded to
`384` before the request crosses into the accepted RuntimeService.

`06_llm-runtime` correctly forwards the requested provider options and
correctly rejects malformed JSON. RAG, Safety, CAT, Database, Frontend and
Frozen Root are not owners of this bug.

## 12. Candidate Fixes Considered

### Recommended: Class B — provider request fix

Raise the Backend request's `max_output_tokens`/Ollama `num_predict` from
`384` to `768`. The exact prompt then produces a complete structured object at
`eval_count=742` with `done_reason=stop`. This preserves the prompt, exact
provenance, schema, model, digest, context, KV type, parallelism and public
Contract.

### Rejected as unnecessary: Class A — prompt/evidence serialization change

Escaping or delimiting the evidence can change model response length, but it
would change the LLM-facing representation and is not needed once the proven
budget defect is corrected. No citation projection is authorized or required.

### Rejected: Class C — Runtime parser change

The parser is receiving malformed JSON and is behaving correctly. Changing it
would weaken the failure boundary.

### Rejected: Class D — citation slot projection

Exact IDs are not being dropped or mutated, and a budget change resolves the
failure without an identity layer.

## 13. Rejected Workarounds

The following remain forbidden and were not used: neutral IDs in product
acceptance, D2 corpus substitution, schema weakening, structured-output
bypass, malformed JSON acceptance, regex extraction, JSON repair, blind retry,
model/quantization/version switching, CPU as primary, cloud fallback,
temperature randomization, provenance dropping, or citation disabling.

## 14. Recommended Minimal Fix

Change only the Backend provider request budget to `768`, add a deterministic
synthetic regression that fails on the truncated structural class and passes
with the complete required object and exact citation mapping, then run the
formal provider/runtime checks and the existing GPI harness. The fix is not
accepted by this report alone; normal 3/3, Output Safety, citation round trip,
trace/GPU correlation, persistence and required regressions must still be
verified.
