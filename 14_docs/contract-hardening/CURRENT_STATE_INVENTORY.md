## 7. Error boundary inventory

The existing implementation has one RFC 9457-style runtime path in
09_backend/src/smhai_backend/core/errors.py. It returns
application/problem+json with type, title, status, detail, instance, code,
retryable, request_id, and trace_id.

Current gaps:

- ProblemDetails is a plain serializable class, not a declared Pydantic DTO.
- route decorators do not document the problem media/schema;
- validation errors discard field-level error details;
- the frontend adapter can fall back to human detail/message without a typed
  error catalogue;
- runtime cookie and CSRF checks are not represented by source security
  declarations.

No second error framework is allowed; this existing handler path is the one to
harden.

## 9. Provenance and execution-state trace

The RAG chunk currently carries chunk_id, document_id, content_hash,
citation, location, review status, rights status, and embedding metadata.
The orchestrator reduces it to chunk.citation for SupportResult.citations,
dropping chunk/document/hash/rank identity. The MySQL adapter hashes
title/organization/locator into a new citation, writes source_hash=None, and
the report reconstruction path does not read support_evidence into the API
projection. The report API therefore loses persisted citations.

The accepted evidence makes this observable: normal SupportResult records five
citations, while the replayed report projection records only one derived
citation; crisis and unsafe cases expose no citations.

The blocked-generation path also carries model_id MODEL_backend_fake with
model_version/runtime_version not_used when the crisis path intentionally
makes zero RAG/LLM calls. The candidate must represent this as
generation_status=NOT_RUN and model_id=null. Controlled synthetic output must
be explicitly labelled and must never masquerade as executed model identity.
The frozen generation.v1 root schema is not changed to achieve this.
