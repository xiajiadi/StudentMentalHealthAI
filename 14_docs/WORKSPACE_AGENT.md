# PsyNova 智能体工作区

公网合成学校可用自然语言发送任务。首次发送时，页面会说明 DeepSeek 的用途以及名单的处理方式。四个角色各自有一份可重新打开的会话。个人测评题目、原始作答、名单、初始凭据和专业档案由现有产品组件和业务接口处理。

## 运行方式

1. 后端根据登录会话确定学校和角色，再由学校本地 Safety 服务检查输入。只有通过检查的合成体验消息可以进入 DeepSeek。
2. DeepSeek 根据当前角色的工具定义提出调用。后端校验工具、参数和角色，调用原业务服务，将有限的结果返回给模型。
3. 浏览器显示实际调用、结果、响应和中断。名单、作答和专业工作台接受受控的业务数据。模型可以提出操作，用户在产品组件确认后才会发生业务写入。
4. 日志记录追踪号、模型返回的调用标识、工具名称和结果状态。服务端最多保留每个工作区最近的 160 条事件。超过七天未更新的会话停止返回，并在新的运行开始时清理。浏览器断开后，已开始的任务由服务端继续执行，重开工作区时自动读取同一任务的进度。需要停止时可主动取消。服务进程异常退出后，旧任务会被标记为中断，用户可重试筛查通过的文字任务。涉及附件的任务需要重新添加文件，已经提交的业务操作以原系统记录为准。

多轮查询保留已选择记录的引用。数量、状态和发布日期在新一轮查询时重新从学校服务读取，过往查询仍留在浏览器会话供用户查看。

任务通过输入检查后，运行期间可从同一个输入框发送补充。服务端将补充绑定到当前账号、学校和角色的那次运行，停止旧运行，重新检查原要求和新要求，再调用模型。已完成并通过检查的原稿仍可通过文档工具继续使用。业务数据需要重新查询；已另外确认提交的业务操作以原系统记录为准。

通用任务无需自动检索心理知识库。遇到学习压力、认识情绪、睡眠习惯或向信任的人开口等科普问题，模型可查询 PsyNova 已上线的对应资料。心理安全处理和正式业务审批沿用各自的既有服务。

运行时采用已有 DeepSeek 服务的函数调用。后端将实际结果送回模型，并把执行记录留在各自的工作区。工具数量不多，当前按登录角色提供目录。交互组件固定在 Vue 代码里，模型输出只能选择组件类型与受限参数。设计参考了 [Codex Agent Loop](https://openai.com/index/unrolling-the-codex-agent-loop/)、[Codex App Server](https://openai.com/index/unlocking-the-codex-harness/)、[Anthropic 的上下文工程](https://www.anthropic.com/research/effective-context-engineering-for-ai-agents) 和 [DeepSeek Tool Calls](https://api-docs.deepseek.com/guides/tool_calls/)。

| 普通教师支持转介 | 根据教师描述准备草案，教师在会话内选择授权学生、编辑并提交。可查询授权支持请求的处理状态 | 原支持请求、班级权限和状态查询服务 |
| 心理教师 CAT 与资料 | 上传合成 GRM JSON 或 CSV 后可在会话中校验题库、准备方案、确认保存，再单独批准合成施测并交接 | 原 CAT 验证、题库版本、方案版本和合成施测审批服务 |
| 心理教师复核与支持工作 | 汇总指派范围内已完成但尚未建立复核记录的测评，以及已建立的待复核记录。可从会话直接打开本人最近受理、仍待制定计划的请求，再核对已发布反馈、引用版本、选用公开科普、编辑并确认保存 | 原专业复核指派和支持请求权限，现有公开资料。个案记录、反馈和计划正文留在私有工作台，模型只收流程数量 |

| 管理员教职工导入 | 添加教职工模板 CSV 或 XLSX，在对话中核对普通教师、心理教师和任教班级。管理员确认后签发一次性凭据，可下载账号表并重新查询邀请状态 | 原教职工导入、班级目录、邀请和凭据服务。模型收到名单类型及邀请统计 |
| 管理员班级与发布 | 在对话中确认新建班级、发布默认合成测评或发布已批准的 CAT 交接。CAT 发布绑定具体的审批和方案版本 | 角色鉴权、任务发布和审计接口 |
| 管理员运营记录与系统状态 | 用自然语言检查依赖状态，按学校、班级、成员、账号批次、账号或任务查询运营记录并继续翻页 | 原系统依赖检查和本校运营审计服务。展示白名单内的记录，不发送内部记录编号、账号或原始日志 |
| 通用问答和报告 | DeepSeek 回答合成体验中的通用任务，生成可下载的 Markdown 或可编辑 Word 文档 | 输入和生成内容经过本地检查，Word 文件由浏览器根据同一份报告生成 |
| 文字与练习图片 | TXT 和 Markdown 可在浏览器预览。PNG、JPEG 或 WebP 可读取中英文文字。可估算普通柱高、堆叠柱各段及合计，并读取共用线性纵轴的彩色折线图。读数可对照原图、编辑并插入输入框 | 浏览器读取文件，图片使用同源部署的 Tesseract.js 及本地像素分析，确认发送的文字经过既有安全检查 |
| 手写公式预览 | 整页练习图可在本机标出候选公式，用户可逐道选择或手动框选，也可直接识别单道公式图。核对结果后，可将公式和题干一起加入对话 | 浏览器只将用户确认的区域转写为无原文件名和元数据的 PNG。学校服务本地运行公式识别，公式预览不进入对话历史 |
| 文档摘录与本校资料 | PDF 和 DOCX 可提取文字，并选择段落交给智能体。心理教师可从预览进入本校资料库，确认导入并检索 | 学校服务的隔离解析、原资料库权限和索引。文档预览使用临时文件，正文由用户明确选择后才进入输入框 |
| 学生与教师表格分析 | 在浏览器选择 CSV 的列或 XLSX 的工作表及列，查看并下载数字个数、最小值、最大值、平均值和合计 | 由浏览器计算，只有选择的列号和统计值会发送。文件名、工作表名、列名和逐行数据留在本机 |

CAT 会话上传接受最多 240 KiB 的合成 GRM JSON 或 UTF-8 CSV。CSV 沿用独立工作台的 `id,stem,model,a,thresholds,options,content` 列格式，`thresholds` 与 `options` 填 JSON 数组，`content` 可留空且不参与学校模板的计分或选题。CSV 要求每次选择文件后确认合成用途，使用学校现有的单维 GRM 工程模板。CAT 原文由学校服务校验，模型收到题数、维度数和配置是否齐全等摘要。保存题库和方案、心理教师批准施测、管理员发布各有独立的确认步骤。此流程用于合成工程施测。

表格分析使用第一行作为列名。单个工作表最多 40 列、2,000 行数据。XLSX 文件最多 2 MiB、8 个工作表，由浏览器的独立线程读取，限制解包大小和处理时间。Excel 公式使用文件中已保存的数值，文字格式的数字不计入统计。结果可下载为 CSV。

学校名单的 XLSX 只导入第一个工作表，按现有学生或教职工模板校验，最多 1 MiB 和 3,000 条数据。浏览器核对教职工表头后，将名单带入私有导入组件。模型只收到附件类型。

Word 导出把报告里的 Markdown 标题、列表、表格和 HTTP/HTTPS 来源链接转成 Word 元素。只有点击导出时才加载生成模块。下载使用浏览器已有的报告内容，无需再调用模型。原 Markdown 也可单独下载。[Marked 结构解析](https://marked.js.org/using_pro) [docx 文档生成](https://docx.js.org/)

折线图最多估算四条颜色清晰可分、共享一个线性纵轴的连续曲线。堆叠柱按共同的零刻度估算每组二至四个连续纯色段，要求各柱颜色顺序一致。清晰的上方图例可补充名称，图例对应不清时只显示颜色。双纵轴、同色重叠曲线、无法跟踪的数据或颜色段缺失时保留文字预览。公式候选最多八处，主要覆盖浅底练习图的分数结构和文字识别能分辨的简单行内算式，边界可手动调整。其他复杂图表、图片中的几何图形、复杂混排公式、更多通用附件格式、个人正式测评结果的专业解释，以及专业支持计划对获准读取的计分结果和获批风险规则的使用仍需补齐。当前学校权限只允许学生读取本人的正式计分记录。公开合成测量使用工程验证题库及规则标识，支持核对算法估计值和标准误。后端测试覆盖同轮多步调用、角色与学校隔离、CAT 文件出站限制、反馈正文的私有读取，以及多轮查询重新读取业务状态。

## 部署和恢复

部署脚本位于 13_deployment/deploy_workspace_agent_demo.sh，适用于现有合成公网服务器。用审核后的后端补丁、模型服务补丁和真实 API 模式构建的前端准备独立发布目录。先执行 stage，再执行 activate。确认模型和业务链路后执行 publish。发布使用独立服务配置和前端目录，现有业务库无需迁移。执行 rollback 可恢复原来的服务配置和前端链接。

公式预览使用可选的本地运行目录 `PSYNOVA_WORKSPACE_FORMULA_DIRECTORY`。在目录内用 `13_deployment/requirements/psynova-formula-preview.txt` 安装独立的 `venv`，并将同一上游修订的 `encoder_model.onnx`、`decoder_model.onnx`、`tokenizer.json` 放入 `model`。学校服务账号只需读取运行目录。公网使用修订 `1cef9f0bdcd6a4c63df7de1311fb0894593340cc`。模型文件由部署阶段核对，运行时从本地读取。[Pix2Text MFR 1.5 模型卡](https://huggingface.co/breezedeus/pix2text-mfr-1.5/tree/1cef9f0bdcd6a4c63df7de1311fb0894593340cc)

校内反馈导读用 `PSYNOVA_WORKSPACE_FEEDBACK_DIRECTORY` 指向只读运行目录，复用公式识别的 ONNX Runtime、NumPy 和 Tokenizers 环境，并共用一个模型任务名额。公网使用修订 `75c43b069aac4d136ba6bc1122f995fedcfd2781` 中的 `onnx/model_uint8.onnx` 和 `tokenizer.json`，置于运行目录的 `model` 子目录。部署时核对文件校验值。Linux 子进程用 libseccomp 限制网络套接字，通过标准输入接收问题和当前反馈的原句，只把排序分数交还校内服务。相似度仅用于决定是否展示相关原句。[智源 BGE 模型卡](https://huggingface.co/BAAI/bge-small-zh-v1.5) [固定版本 ONNX 文件](https://huggingface.co/Xenova/bge-small-zh-v1.5/tree/75c43b069aac4d136ba6bc1122f995fedcfd2781/onnx)
