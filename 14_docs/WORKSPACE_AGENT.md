# PsyNova 智能体工作区

公网合成学校可用自然语言发送任务。首次发送时，页面会说明 DeepSeek 的用途以及名单的处理方式。四个角色各自有一份可重新打开的会话。个人测评题目、原始作答、名单、初始凭据和专业档案由现有产品组件和业务接口处理。

## 运行方式

1. 后端根据登录会话确定学校和角色，再由学校本地 Safety 服务检查输入。只有通过检查的合成体验消息可以进入 DeepSeek。
2. DeepSeek 根据当前角色的工具定义提出调用。后端校验工具、参数和角色，调用原业务服务，将有限的结果返回给模型。
3. 浏览器显示实际调用、结果、响应和中断。名单、作答和专业工作台接受受控的业务数据。模型可以提出操作，用户在产品组件确认后才会发生业务写入。
4. 日志记录追踪号、模型返回的调用标识、工具名称和结果状态。服务端最多保留每个工作区最近的 160 条事件。超过七天未更新的会话停止返回，并在新的运行开始时清理。刷新能恢复已保存的事件。浏览器断开会停止当次处理，已提交的操作以业务系统记录为准。

通用任务无需自动检索心理知识库。心理安全处理和正式业务审批沿用各自的既有服务。

运行时采用已有 DeepSeek 服务的函数调用。后端将实际结果送回模型，并把执行记录留在各自的工作区。工具数量不多，当前按登录角色提供目录。交互组件固定在 Vue 代码里，模型输出只能选择组件类型与受限参数。设计参考了 [Codex Agent Loop](https://openai.com/index/unrolling-the-codex-agent-loop/)、[Codex App Server](https://openai.com/index/unlocking-the-codex-harness/)、[Anthropic 的上下文工程](https://www.anthropic.com/research/effective-context-engineering-for-ai-agents) 和 [DeepSeek Tool Calls](https://api-docs.deepseek.com/guides/tool_calls/)。

## 能力清单

| 场景 | 工作区行为 | 执行依据 |
| --- | --- | --- |
| 学生查询和选择测评 | 查询本人任务，模型可根据结果选择一项打开说明 | 学校任务服务，限域任务别名 |
| 学生作答和提交 | 学生在正式测评组件自行作答，组件保存并提交 | 原状态、作答、完成接口 |
| 学生知识、支持与反馈 | 在对话中打开已有组件 | 既有产品接口和权限 |
| 普通教师进度与报告 | 查询授权班级的任务和完成数量，可按任务开放时段筛选并生成 Markdown | 学校进度服务和本地安全检查 |
| 普通教师支持转介 | 在对话中打开转介工作台 | 既有教师转介流程 |
| 心理教师 CAT 与资料 | 模型可打开题库、测评方案和专业资料工作台 | 既有解析、验证和审批逻辑 |
| 心理教师复核 | 查询其有权复核的任务，工作台显示业务内容 | 既有专业复核服务 |
| 管理员人数核对 | 查询本校学生账号和班级人数 | 学校目录服务 |
| 管理员名单导入 | 添加 CSV 或 XLSX 文件时直接打开受控预览。管理员确认后建班、导入并签发凭据 | 原花名册、账号和凭据接口 |
| 管理员班级、发布和系统状态 | 新建班级和默认合成测评发布都可在对话中预览、确认并执行。自定义方案使用发布工作台 | 角色鉴权、任务发布和审计接口 |
| 通用问答和报告 | DeepSeek 回答合成体验中的通用任务，可生成 Markdown | 输入和生成内容经过本地检查 |

CAT 文件到正式方案的连续自动编排、图片理解、个人测评结果的私有推理，以及跨工作台转交给模型的执行回执仍需补齐。后端测试覆盖同轮多步调用、角色和学校隔离，以及未通过本地检查的文本不会出站。带模拟模型的测试用于验证约束。

## 部署和恢复

部署脚本位于 13_deployment/deploy_workspace_agent_demo.sh，适用于现有合成公网服务器。用审核后的后端补丁、模型服务补丁和真实 API 模式构建的前端准备独立发布目录。先执行 stage，再执行 activate。确认模型和业务链路后执行 publish。发布使用独立服务配置和前端目录，现有业务库无需迁移。执行 rollback 可恢复原来的服务配置和前端链接。
