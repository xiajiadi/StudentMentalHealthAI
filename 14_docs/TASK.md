# 14_docs：项目、开发与研究文档

## 职责

- 将已确认的架构、运行方式、接口和限制写成可复用文档；
- 维护用户、开发者、管理员、研究记录和演示说明；
- 记录每阶段实际完成内容、证据、未覆盖范围和决策；
- 让文档与代码、Contract、截图和测试结果保持一致；
- 为项目负责人准备可审阅的交付摘要。

## 输入

- 根级治理文件和各模块交接；
- 实际测试、部署和演示记录；
- 已确认的产品、伦理、隐私和安全要求；
- 经批准的 UI 文案和研究材料。

## 输出

- 开发/运行/排障文档；
- 用户和角色使用说明；
- Contract/模块索引；
- 版本说明、变更记录和限制声明；
- 阶段验收记录和证据目录。

## 禁止事项

- 不编造功能、运行结果、专家评价、研究数据或截图；
- 不把概念图、Mock 界面或合成案例称为真实产品/试点证据；
- 不擅自修改核心 Contract 或技术决策；
- 不隐藏高风险限制、未完成项和环境差异；
- 不在文档中暴露密钥、真实身份信息或未脱敏测评内容。

## 接口

- 从根级文档和模块 TASK.md 获取规范；
- 引用测试报告中的实际版本和范围；
- 文档中的端点、字段、状态和启动命令必须能回到唯一来源；
- 新增用户可见文字执行 Humanizer -> Vale；
- 文档变更需要列出事实来源、验证时间和未确认内容。

## 验收标准

- 新 Agent 能按文档理解工程边界并启动对应模块；
- 用户文档不要求用户了解内部模型细节；
- API/Contract/运行说明与当前实现没有已知矛盾；
- 限制、数据性质、人工复核和非诊疗边界清楚可见；
- 文案经过人工化审阅，若没有 Vale 配置则明确说明未运行；
- 阶段报告区分“已实现”“已验证”和“待确认”。

## 交付物

- 文档目录和索引；
- 用户/开发/管理员/研究/排障文档；
- 阶段交付记录模板；
- 变更日志和限制清单；
- 面向负责人和答辩的事实性项目摘要。
