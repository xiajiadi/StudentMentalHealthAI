# 12_evaluation：测试、指标与研究证据

## 职责

- 建立合成案例、边界案例和高风险案例；
- 对四项 Contract、模块行为和端到端链路执行回归；
- 评估 CAT 技术指标、RAG 检索质量、生成结构/引用质量和安全行为；
- 记录模型、Prompt、知识、规则和配置版本；
- 将系统可运行性、输出质量和研究效果分开报告。

## 输入

- 各模块 fixture 和实际输出；
- CONTRACTS.md、expected behavior 和验收标准；
- 合成受试者、知识检索查询和生成案例；
- 专家评价表或用户评价方案（经批准后）。

## 输出

- Schema/API/模块/集成测试；
- RMSE、Bias、平均题数、检索命中/引用完整性等技术指标；
- 生成质量和安全测试报告；
- 失败样例、回归基线和已知限制；
- 可复现的实验记录。

## 禁止事项

- 不把合成数据伪装成真实试点；
- 不编造学生成绩、心理状态、专家评分或效果显著性；
- 不把通过自动测试等同于临床有效、安全绝对或研究结论；
- 不擅自改变风险阈值、题库参数或 expected behavior 以让测试通过；
- 不在测试报告中暴露真实敏感信息。

## 接口

- 输入/输出均按对应 Contract 校验；
- 通过 Mock Provider 测试无模型路径；
- 通过 Safety Engine 测试 allow、warn、block、needs_review；
- 保存 test_case_id、fixture_version、component_version 和结果；
- 生成报告时明确测试范围、环境和未覆盖范围。

## 验收标准

- 普通、边界、高风险三类案例均有 expected behavior；
- 缺字段、错误枚举、无引用、模型失败和权限失败有负向测试；
- 结果可由固定 fixture 和配置重跑；
- 安全阻断和人工复核路径没有回归；
- 技术指标与研究效果没有混写；
- 每份报告都列出数据性质、环境、版本和限制。

## 交付物

- 合成案例库和 fixture 规范；
- 单元/契约/集成/回归测试；
- CAT、RAG、生成和安全评估报告；
- 研究记录模板；
- 发布前验证清单。
