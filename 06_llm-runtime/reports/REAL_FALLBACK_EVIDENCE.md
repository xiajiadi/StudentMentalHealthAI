## Controlled test design

The test used an in-memory Test Registry containing:

| Role | Logical model | Provider model |
| --- | --- | --- |
| Primary | `qwen2.5-controlled-missing-primary` | `smhai-acceptance-missing-model:round1` |
| Fallback | `qwen2.5-1.5b-engineering-fallback` | `qwen2.5:1.5b` |

The primary ID is deliberately absent from the live Ollama model list. The
request still went through the real `OllamaProvider` and returned an actual
HTTP 404/model-not-found error. The Ollama service remained alive; the test
did not kill or restart it between primary and fallback. The fallback request
then used the downloaded real `qwen2.5:1.5b` model.

Only `ollama` was registered in the test provider map and the registry had
`cloud_fallback=false`.
